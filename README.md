# RepHub

个人使用的原生 macOS Git / Subversion 客户端。使用 SwiftUI 和 AppKit；版本控制工具通过独立 Swift 模块接入，主界面不嵌入网页。

## 当前版本：获取、读取、更新与提交

- 从菜单、工具栏或 ⌘O 的统一“打开仓库”入口打开本地目录、克隆 Git，或浏览 SVN 后检出选定子目录；获取和更新显示实际阶段及文件／传输记录。
- 自动识别 Git、SVN，以及同目录内的双重管控；从当前工作区内的工具选择器切换读取来源。
- 工作区提供“全部文件 / 变更”两种文件树；目录展开时按需读取，未修改的文本文件可只读预览，变更文件继续显示差异。打开后自动读取首个代码变更。
- 差异支持并排 / 统一切换、真实行号、增删底色与基础词法高亮；长代码可横向滚动。
- 大型差异每段最多 300 个对照行，支持跳转任意段；保留全部段、行号及增删底色，暂不进行逐行语法高亮，避免大文件阻塞窗口。
- 历史采用分支栏、提交表格 / Git 图谱、右侧详情与下方差异，支持分支引用和提交搜索。Git、SVN 与文件历史均先读取最近 150 条；点击底部“加载更早”或滚动至末尾会继续读取更早记录，刷新从首批重新读取。搜索只筛选已经加载的记录。
- 分支按名称中的 `/` 分组为目录，提交详情中的文件按真实路径分组；均支持逐层展开、收起和一键全部展开 / 收起。TAB 切换保留文件选择及目录展开状态，并复用已读取的差异。
- 工作区或提交详情中的文件支持右键查看文件历史，也可从历史页选择一个本地文件；文件历史与仓库历史使用相同的首批和续读规则，支持追溯改名和历史差异。
- 历史行显示“待更新 / 待推送 / 需核对”。Git 比较当前分支与已获取的真实上游，SVN 按工作副本或单文件 BASE 判断，混合修订不冒充已同步。详见 [文件历史与同步状态](docs/file-history.md)。
- 原生设置（⌘,）提供温润翡翠 / 石墨灰主题、浅色 / 深色 / 跟随系统，以及独立的代码配色，立即生效并保存。
- SVN 自动识别旧 TLS 握手问题并静默尝试 TLS 1.0–1.3 兼容，无需手动配置；保留现有证书校验。详见 [SVN TLS 兼容](docs/svn-tls-compatibility.md)。
- 命令执行支持超时和取消；快速切换目录、来源或修订时丢弃过期结果。检测失败与未受管理目录分别显示。
- 顶部“更新”支持 Git 获取远端引用、快进更新与 SVN 更新；双管控目录单选一个更新来源，结束后刷新两侧状态。进度、取消、冲突和失败结果均在原生窗口展示。详见 [更新行为与测试边界](docs/repository-update.md)。

- 工作区支持按文件提交到 Git、SVN 或两个已识别目标。每个目标独立选择文件、预览最终差异与填写多行说明，分别保留结果并可跳转历史。Git 仅创建本地提交，未选暂存内容保留。详见 [提交代码](docs/committing.md)。
- 应用采用最终选定的“翡翠分支”图标，打包时生成标准 macOS 图标资源。
- AI 场景支持模型 API（Chat Completions）、Codex CLI、Claude Code。连接与提示词分别配置，密钥使用 macOS 钥匙串；按 Git / SVN 所选文件生成提交说明，或审查工作区和历史提交，支持取消及结果过期核对。详见 [AI 场景与连接](docs/ai.md)。
- 最近打开的仓库会在欢迎页、打开窗口、顶部仓库菜单和“项目 → 最近打开”中显示，重启后保留。最多记录 20 个，重复打开置顶，支持移除和清空；只保存成功识别的本地目录，不保存远程凭据。此功能从升级后首次成功打开仓库开始记录。
- 侧栏、提交详情与上下差异区域均可拖动调整大小；边界随窗口剩余空间计算，只保留最小可见区域，窄栏内容在自身区域内裁剪或滚动。

初始化、暂存区的独立管理和 Git 推送尚未接入。未管理目录只能查看提示，不能初始化。SVN 可使用本机已有认证配置，也可填写只在当前应用会话使用的账号密码；尚无证书信任管理界面。

## 构建与运行

需要 macOS 26 或更新版本、Xcode 26 / Swift 6.2 或更新版本，以及本地 Git。读取 SVN 还需要安装 `svn`；本地 SVN 集成测试另需 `svnadmin`。工具按常见安装目录和当前 PATH 查找。

旧 TLS 兼容要求 SVN 实际加载 OpenSSL 3，本机已验证 Homebrew SVN 1.14.5 / OpenSSL 3.6.3；不满足时显示明确提示。协议矩阵测试另需 Homebrew OpenSSL 3。

```sh
swift test
./scripts/build-app.sh
open build/RepHub.app
```

也可以在 Xcode 中打开 `Package.swift`。打包脚本生成本地临时签名的 `.app`，不是公证分发包。构建产物在 `build/` 与 `.build/`，不纳入 Git。

## 模块

| 模块 | 职责 |
| --- | --- |
| VersionControlCore | 提供者契约、能力、仓库 / 文件 / 修订模型 |
| ToolExecution | 无 shell 的参数数组执行、工具定位、输出上限与超时取消 |
| GitAdapter / SVNAdapter | 具体命令构造和输出解析 |
| RepositoryApplication | 多提供者识别、读取、写操作互斥、多目标提交与全绑定刷新，只依赖契约 |
| DesignSystem | 独立的应用主题、代码配色、外观模式及持久化 |
| AICore / AIApplication | 独立 AI 契约、连接及场景配置、凭据引用与执行编排 |
| AIAdapters | Chat Completions、Codex / Claude CLI 及 macOS 钥匙串适配 |
| RepHubUI | 原生工作区、差异、历史图与设置交互 |
| RepHubApp | 窗口、菜单、依赖组装 |

更新测试在独立 Git / file:// SVN 仓库中执行，自动化测试使用隔离 HOME 和工具配置，不使用业务仓库。`python3 scripts/create-update-fixtures.py` 可建立可重复的原生界面验收样本，所有远端和副本均位于 `系统临时目录/RepHub-UpdateFixtures/<uuid>`。原生架构与后续流程边界见 [架构说明](docs/native-architecture.md)，完整目标见 [需求](docs/requirements.md)。

文件历史和同步状态的界面样本使用 `python3 scripts/create-history-fixtures.py` 创建，位于 `系统临时目录/RepHub-HistoryFixtures/<uuid>`；包含 Git 分叉与中文改名文件，以及 SVN 待更新、改名和混合修订样本。

目录树与性能样本使用 `python3 scripts/create-tree-fixtures.py` 创建，位于 `系统临时目录/RepHub-TreeFixtures/<uuid>`。包含多级分支、嵌套提交文件、未修改文件、长行及 10,000 行差异。全部文件模式展示本地文件（排除 `.git` / `.svn` 管理目录），搜索仅筛选已读取的目录；外部文件变更后使用刷新重新读取。文本预览上限 1 MiB，二进制与符号链接显示提示，不跟随链接读取。

## 下一阶段

后续接入独立 Git 推送、未管理目录初始化和冲突处理；AI 按实际服务需求扩展协议及上下文能力。新增 SVN 写操作继续遵循先只读探测 TLS、再单次写入，不能无感重试可能已经执行的写命令。

提交实窗样本可用 `python3 scripts/create-commit-fixture.py` 创建在系统临时目录，包含共管仓库和预先暂存但可不勾选的文件，用于验证提交范围及状态保留。
