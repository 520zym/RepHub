# 提交代码

在工作区底部勾选已有的 Git／SVN 来源，点击“提交”打开准备窗口。窗口中可以分别启用目标、勾选文件、点击文件预览差异，并为每个目标填写多行说明。最终按钮会标明 Git 本地与 SVN 服务器各自的文件数。

- Git 提交所选文件当前的工作区版本；即使文件之前仅暂存了一部分，本次也会使用整个文件的工作区版本。未选文件的暂存内容保留，提交不会推送。
- SVN 直接提交到服务器；未跟踪文件按需加入版本管理，新增父目录只包含必要路径，不递归带入未选文件。若提交失败，本地可能保留已调度添加的状态。
- 两边同时启用时先提交 Git，再提交 SVN。分别保留结果，普通失败不会回滚已成功目标；取消或无法确认结果时停止后续目标，不自动重试。
- 提交前会再次检查比较基准和文件快照。预览后发生变化的文件需要重新准备，不能沿用旧预览提交。
- 结果显示实际 Git 提交号或 SVN 修订号，可点击“查看提交”进入对应来源的历史。显示待核实时，应先核对历史及工作区，再决定下一步操作。

当前不处理 Git 合并／变基中的提交、子模块、类型变化和外部过滤器；SVN 目录递归变更、复制／移动等关联范围会提示限制。Git 暂存区的逐行选择、Git 推送及 AI 生成说明仍属于后续功能。

验收样本由 `python3 scripts/create-commit-fixture.py` 创建在系统临时目录，远端只有本地 bare Git 和 SVN `file://` 仓库，不需要业务仓库。
