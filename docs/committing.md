# 提交代码

在工作区右侧填写提交说明；只有多个 Git／SVN 来源时才需要选择提交目标。点击“提交”打开准备窗口，核对文件、预览差异，并分别编辑各目标的说明。最终按钮会标明 Git 本地与 SVN 服务器各自的文件数。

工作区和确认窗口均使用多行说明编辑器，长文本自动换行并可滚动查看；需要更多空间时可在当前页面展开编辑。确认窗口中的提交按钮单独放在底部，不再挤占说明输入区域。取消确认窗口会保留各目标草稿，重新打开后可以继续编辑。

- Git 提交所选文件当前的工作区版本；即使文件之前仅暂存了一部分，本次也会使用整个文件的工作区版本。未选文件的暂存内容保留，提交不会推送。
- SVN 直接提交到服务器；未跟踪文件按需加入版本管理。新增文件夹或已选目录节点仅按 `depth=empty` 加入和提交该节点，绝不递归带入未选子项；已显式选择的叶子文件才会一并提交。若提交失败，本地可能保留已调度添加的状态。
- 两边同时启用时先提交 Git，再提交 SVN。分别保留结果，普通失败不会回滚已成功目标；取消或无法确认结果时停止后续目标，不自动重试。
- 提交前会再次检查比较基准和文件快照。预览后发生变化的文件需要重新准备，不能沿用旧预览提交。
- 结果显示实际 Git 提交号或 SVN 修订号，可点击“查看提交”进入对应来源的历史。显示待核实时，应先核对历史及工作区，再决定下一步操作。

SVN 提交后，已提交文件的 BASE 会前进，而其他节点可能保留旧版本，形成正常的混合修订。历史页面会核对混合范围最高修订涉及的普通新增／修改文件：本地 BASE 和仓库路径均匹配时显示已同步，无需额外执行“更新”。只更新部分文件，或涉及目录、删除、复制等不能完整证明的情况，仍保留“需核对”；此判断不修改工作副本。

当前不处理 Git 合并／变基中的提交、子模块、类型变化和外部过滤器；SVN 目录递归变更、复制／移动等关联范围会提示限制。Git 暂存区的逐行选择仍属于后续功能；Git 推送通过“仓库 → 推送…”作为独立、显式确认的管理操作提供。

所选目标的提交说明旁可点击“AI 生成”，确认生成结果后填入并继续编辑；文件或基准变化时旧结果不能填入。详见 [AI 场景](ai.md)。

验收样本由 `python3 scripts/create-commit-fixture.py` 创建在系统临时目录，远端只有本地 bare Git 和 SVN `file://` 仓库，不需要业务仓库。
