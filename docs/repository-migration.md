# 仓库迁移设计

更新日期：2026-10-12。状态：新增需求与实现设计，尚未编码；当前应用的初始化、克隆／检出和关联目录不提供此能力。

## 1. 已确认的主场景

原项目由 SVN 管理，现在需要转到另一个 Git 仓库。用户确认目标通常是新建的空仓库，希望尽可能带上提交记录；无法转换历史时，可以接受只迁移代码。多种版本控制工具之间的迁移需要预留扩展能力。

首个实现方向为 **SVN → 空 Git 仓库**，支持选定 SVN 子目录。当前按一次性迁移设计，不包含持续双向同步。目标已有历史时停止空仓库流程，解释检测结果；已有历史的合并策略另行实现，不隐式拼接、重写或覆盖。

## 2. 用户流程

1. 从“项目 → 迁移仓库…”进入，可从当前仓库绑定预填来源；同目录双绑定时明确选择来源。
2. 填写或浏览 SVN 来源目录，输入目标 Git 地址、目标分支及新的本地目录。
3. 执行只读预检：确认来源可访问、固定源修订、读取所选范围的历史和作者，检查目标是否为空及本地目标是否可用。空仓库的可读检查不能证明用户具有推送权限，最终发布仍可能被服务器拒绝。
4. 展示迁移计划：来源路径／修订、历史范围和条数、作者映射、分支与标签处理方式、预计不能保留的内容。默认选择保留历史；只有用户明确选择才切换为“仅迁移此版本代码”。
5. 在独立目录转换，展示阶段、当前修订／总条数及实际文件记录；有阶段总量时才显示百分比，不将逐文件进度伪装为整项任务进度。
6. 进入独立的“转换预览”步骤，查看实际生成的文件树、代码差异、导入历史、源修订映射、遗漏项和警告，具体见下节。文件、历史或权限读取不完整时不能显示完整迁移成功。
7. 用户点击“发布到目标 Git”后重新检查目标，再推送明确的分支／标签范围。发布完成后读回目标引用核对，随后可打开新的 Git 工作区。

原仓库和原工作副本不改动；不在原 SVN 目录直接建立 `.git`，也不自动删除 `.svn`。未提交的本地修改默认不混入源历史，预检时单独提示。迁移期间来源新增的提交不纳入已固定的本次范围，结果中标明来源截止修订。

### 2.1 转换预览

用户明确要求能够预览转换结果。预览包含两个阶段，分别标明“预计迁移”和“实际转换结果”：前者来自只读预检，后者来自独立目录中已经生成且经过核对的仓库，不能拿预估条数或示例数据替代实际结果。

实际结果预览沿用原生工作台的树状文件、差异和历史组件，通过“概览／文件／历史”切换，避免将全部信息堆在一个确认弹窗中。

| 预览区域 | 展示内容与操作 |
| --- | --- |
| 概览 | 来源类型、目录和固定修订 → 目标类型、地址与分支；所选历史模式；源范围内记录数、已生成提交数、已核对数及未迁移数分别展示；本地转换状态与远端尚未发布状态分开显示 |
| 文件 | 转换后的文件树，可展开／收起、搜索和筛选差异；显示原路径到目标路径的映射及一致、已转换、未迁移、核对失败状态；选择文件后查看源固定修订与生成结果的并排／统一差异 |
| 历史 | 转换后的提交列表及实际父子关系，支持分页查看完整范围；源 SVN 修订号与目标 Git 提交号对应展示，选择记录可查看作者、时间、说明和该次文件变化；占位邮箱或其他元数据转换明确标记 |
| 差异与限制 | 单独列出空目录、属性、忽略规则、外部引用等处理结果，区分计划内转换、经用户选择的省略和阻断问题；不能把未核对项归入一致 |

文件核对的基准是源固定修订，不是空的目标远端；不能把所有文件都标成“新增”来替代转换正确性检查。文本可查看具体差异；二进制显示大小及内容校验结果；目录、符号链接和可执行位按类型展示。界面截断的大文件、未读取的历史或未完成的核对必须有明确标记，不能因预览仅展示部分数据就宣布全部一致。

预览底部提供“返回调整”“保留本地结果”和“发布到目标 Git”。核对未完成或存在阻断问题时，不允许发布。用户返回修改范围、作者映射、历史模式等转换参数后，旧预览失效，需重新生成；不能沿用旧结果的确认状态。

发布绑定预览对应的源修订、转换策略、结果清单和目标提交／引用。发布前再次核对本地结果未变、目标仍满足计划；有变化时返回核对并更新预览。来源服务器后来新增提交时保持本次固定范围，提示截止修订，不静默替换已预览内容。进入、浏览或退出预览均不写入目标远端。

## 3. 历史保留与转换差异

下表是设计时的能力判断，不是当前实现清单；每个适配器必须通过预检决定具体可用模式。

| 转换方向 | 历史处理目标 | 需要明确的限制 |
| --- | --- | --- |
| SVN → Git | 导入可重建的文件变化、原作者、原提交时间与说明；保存 SVN 修订到 Git 提交的映射 | Git 生成新的提交号；SVN 的复制／合并、目录属性与空目录没有完全相同的 Git 表达 |
| Git → Git | 未重写时保留所选分支／标签可达的提交对象和父子关系 | 仓库托管平台的 issue、PR、权限、钩子不属于 Git 对象；LFS 和子模块内容需另行处理 |
| Git → SVN | 按能力重放指定历史或导入单个代码快照 | 合并图不能原样表示为 SVN 线性修订；原作者和日期的写入受服务器修订属性权限限制 |
| SVN → SVN | 有相应访问与修订属性权限时评估 dump/load 或镜像 | 普通检出／提交权限不保证能恢复原历史；指定子目录的路径重写、复制来源及授权范围需预检 |

SVN → Git 的首个流程以所选目录的一条历史序列为基础。`trunk/branches/tags` 整库转换需要显式路径映射，不能把每个普通目录自动认作 Git 分支或标签。目录改名／复制的祖先历史只有在可读取且可重建时才导入；不能仅按日期生成伪造的合并关系。

作者映射允许把 SVN 登录名对应到 Git 姓名和邮箱。SVN 本身没有提供的邮箱不能猜测成真实邮箱；使用占位值时需要在计划和结果中明确标记。原提交时间作为 Git 作者时间保留，迁移生成时间与原时间分别说明。

空目录、忽略规则、自定义属性、`svn:externals`、可执行位、符号链接、换行与关键字展开分别核对。未读取的 externals 不默认为迁移成功；需要占位文件或规则转换时先说明这会改变文件树。源码快照模式仅产生新的初始提交，并保留来源修订信息，不伪装成原有完整历史。

Git 官方提供 `git svn` 导入能力，但不能直接认定它会沿用 RepHub 现有 SVN 命令的 TLS 回退。实现选型需验证其依赖环境；不兼容时通过现有 SVN 适配器的只读命令导出历史与快照，再交给 Git 目标适配器转换。不得降低全局 TLS 或绕过证书检查。

## 4. 独立契约与执行边界

以下名称为拟议契约，未加入源码：

- `RepositoryMigrationCapability`：来源／目标组合、历史保留等级、分支／标签／属性能力及限制。
- `RepositoryMigrationRequest / Plan`：源路径、固定修订、目标、本地新目录、历史模式和映射策略；计划包含预检得到的状态指纹。
- `RepositoryMigrationSourceProvider / TargetProvider`：分别承担只读导出、目标格式生成与发布；工具命令、解析及认证仍在适配器内。组合专属的转换器可补充处理历史拓扑，不强迫所有工具都模拟 Git。
- `RepositoryMigrationService`：编排预检、独立暂存、转换、核对、发布和中断恢复；界面只接收结构化进度与结果。
- `RepositoryMigrationResult / Manifest`：记录固定来源、策略、源修订到目标提交的映射、代码核对结果、未迁移项及远端发布结果。

迁移不复用“未受管控目录初始化”的单选状态，也不复用工作区按文件提交的请求。现有获取流程的独立暂存、凭据脱敏、取消与进度模型可以复用，但迁移本地转换成功和目标发布成功必须分别表达。

目标复核发现任何已有分支、标签或初始提交时，首个空仓库流程停止。最终写入还需使用目标适配器提供的创建条件保护，避免预检后的并发变更被覆盖；服务端无法提供同等级条件时必须暴露这一限制。拒绝强制覆盖已有引用。

检查点和清单只保存非敏感信息。中断后保留隔离结果，只有来源固定修订、转换策略与生成对象均核对一致时才允许继续；不能盲目重放已完成的远端写入。发布超时或取消可能已经改变远端，先读回引用核对，不能自动重推，也不能自动回滚远端。

## 5. 隔离验收

开发和自动验证只使用临时 Git 裸仓库、本地 SVN 服务及模拟故障，不对用户业务仓库执行迁移、提交或推送。

- SVN 多作者、多修订、增删改、二进制、中文／空格路径，核对历史条数、作者时间、说明和最终代码。
- 指定子目录及复制／改名历史，确认范围外文件不混入；无权读取的祖先明确失败或由用户选择快照。
- SVN 属性、空目录、符号链接、可执行位、externals，逐项检查报告与实际转换一致。
- 长历史分页与断点、取消／重试、读取中断、磁盘不足，确认不静默截断历史、不污染原工作副本。
- 非空 Git 目标、预检后目标变化、无推送权限、分支保护、推送响应丢失，确认无覆盖且可核对最终状态。
- 只迁移代码的显式选择、未提交修改提示、凭据脱敏、旧 TLS 读取路径以及原生界面进度与结果预览。
- 预览的文件树、差异、完整分页历史与实际生成仓库一致；源修订／目标提交映射可定位，预计数量与已核对数量不混用，二进制和未核对项不会显示为文本一致。
- 修改转换参数使旧预览失效；核对失败阻止发布；预览后本地生成结果或目标远端变化可被检测，实际发布内容与最终预览一致；只查看或退出预览不产生远端写入。

## 6. 技术依据

- [Git 官方 git-svn 文档](https://git-scm.com/docs/git-svn)：导入、作者映射、分支布局、空目录与跨工具历史限制。
- [Pro Git：Migrating to Git](https://git-scm.com/book/en/v2/Git-and-Other-Systems-Migrating-to-Git)：SVN 导入及分支／标签整理。
- [Subversion Book：Repository Maintenance](https://svnbook.red-bean.com/en/1.8/svn.reposadmin.maint.html)：dump/load、svnrdump、svnsync 与目标修订属性权限。
- [Git 官方 clone 文档](https://git-scm.com/docs/git-clone)：Git 克隆及引用范围。
