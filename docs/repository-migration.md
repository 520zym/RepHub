# 仓库迁移设计

更新日期：2026-10-15。状态：**SVN 指定目录 → 空 Git 仓库**与**当前 SVN 工作副本接管为 Git + SVN 共管目录**均已接入原生客户端；两种模式已通过本地隔离测试及原生流程验收，实际结果以[原生验证记录](native-verification.md)为准。Git → Git、Git → SVN、SVN → SVN 及已有目标仓库的合并仍未实现。

## 1. 已确认的主场景

原项目由 SVN 管理，现在需要转到另一个 Git 仓库。用户确认目标通常是新建的空仓库，希望尽可能带上提交记录；无法转换历史时，可以接受只迁移代码。多种版本控制工具之间的迁移需要预留扩展能力。

已实现的第一种模式是 **SVN → 空 Git 仓库**，支持选定 SVN 子目录、可读取的线性历史和显式快照模式，并保留“新本地目录 + 空目标远端”的安全边界。第二种已实现的模式面向已有 SVN 工作副本：保留 `.svn`，在同一目录安装 `.git` 并关联新的空 Git 远端；不替换旧模式。

两种模式都不是持续双向同步。空目标模式在目标已有历史时停止；工作副本模式只会在用户明确发起的补迁中，把 SVN 截止修订之后的新提交接续导入 Git，不通过时间或提交说明猜测对应关系，也不隐式拼接、重写或覆盖已有远端历史。

## 2. 用户流程

### 2.1 新目录迁移

1. 从“项目 → 迁移仓库…”进入，可从当前仓库绑定预填来源；同目录双绑定时明确选择来源。
2. 填写或浏览 SVN 来源目录，输入目标 Git 地址、目标分支及新的本地目录。保留历史时可勾选“包含复制前历史”，默认关闭：只迁移所选目录自最近一次创建或复制起的提交；勾选后继续追溯复制来源。
3. 执行只读预检：确认来源可访问、固定源修订、读取所选范围的历史和作者，检查目标是否为空及本地目标是否可用。空仓库的可读检查不能证明用户具有推送权限，最终发布仍可能被服务器拒绝。
4. 展示迁移计划：来源路径／修订、历史范围和条数、作者映射、分支与标签处理方式、预计不能保留的内容。默认选择保留历史；只有用户明确选择才切换为“仅迁移此版本代码”。
5. 在独立目录转换，展示阶段、当前修订／总条数及实际文件记录；有阶段总量时才显示百分比，不将逐文件进度伪装为整项任务进度。
6. 进入独立的“转换预览”步骤，查看实际生成的文件树、代码差异、导入历史、源修订映射、遗漏项和警告，具体见下节。文件、历史或权限读取不完整时不能显示完整迁移成功。
7. 用户点击“发布到目标 Git”后重新检查目标仍没有任何引用，再以“目标分支必须不存在”的条件推送；发布完成后读回目标分支核对，随后可打开本地生成的 Git 工作区。

原仓库和原工作副本不改动；不在原 SVN 目录直接建立 `.git`，也不自动删除 `.svn`。未提交的本地修改默认不混入源历史。迁移期间来源新增的提交不纳入已固定的本次范围，结果中标明来源截止修订。

### 2.2 当前 SVN 工作副本接管

此模式不要求用户新建项目目录，也不替换“迁入新目录”的空目标模式。预览放在应用内部临时目录。首次接管固定当前工作副本 BASE；后续补迁固定远端 SVN HEAD，因此不要求也不会自动更新本地 SVN 工作副本。接管记录保存源仓库 URL、UUID、历史起点、工作副本 BASE／接管点、本次截止修订与累计 SVN→Git 映射；每个生成的 Git 提交同时写入相同范围的来源 trailers。补迁前复核远端 UUID 和最后一个迁移提交的 trailers，不依赖相近的说明或时间推断连续性。

首次接管同样提供“包含复制前历史”，默认关闭；预检及结果显示实际范围、起始修订和条数。首次接管仅接受干净、完整且未切换的 SVN 工作副本：已有受版本控制修改、混合修订、稀疏检出、switched 路径或 `svn:externals` 均拒绝接管；已有 Git 元数据也拒绝覆盖。普通未跟踪文件可以保留，不会被删除、提交、导出或作为拒绝理由；Git 已跟踪文件必须干净。系统不会自动执行 `svn update` 或 `svn commit`。通过预检与隔离预览后，用户明确确认才在原目录安装 `.git`，建立首次 Git 提交并发布到新空远端；`.svn` 始终保留。

后续补迁由用户明确发起。开始前 Git 已跟踪工作区必须干净，且目标远端引用必须等于本地 `HEAD`；系统读取接管标记，从已记录的 SVN 截止修订继续读取。若 Git 在此后存在独立提交，隔离预览以三方 cherry-pick 计算可接续结果；任何冲突均停在隔离预览，不能写入原工作副本或远端。只有用户确认无冲突预览，才将原目录 Git 快进到已核对结果并推送。补迁不自动 `svn update`、不自动 SVN 提交，也不承诺 SVN 和 Git 的持续双向同步。

首次安装 `.git` 与已确认补迁的快进都发生在用户确认之后。工作副本初迁可通过新版检查点跨重启恢复；旧版无检查点任务与补迁暂不支持自动续跑；一旦本地 `.git` 或快进已经应用但远端尚未发布，保留 `origin`，可从现有“仓库管理 → Git 推送”继续发布，不会重新追加 SVN 映射。旧模式已生成结果的检查点恢复边界保持不变。

### 2.3 转换预览

用户明确要求能够预览转换结果。预览包含两个阶段，分别标明“预计迁移”和“实际转换结果”：前者来自只读预检，后者来自独立目录中已经生成且经过核对的仓库，不能拿预估条数或示例数据替代实际结果。

实际结果预览沿用原生工作台的树状文件、差异和历史组件，通过“概览／文件／历史”切换，避免将全部信息堆在一个确认弹窗中。

| 预览区域 | 展示内容与操作 |
| --- | --- |
| 概览 | 来源类型、目录和固定修订 → 目标类型、地址与分支；所选历史模式；源范围内记录数、已生成提交数、已核对数及未迁移数分别展示；本地转换状态与远端尚未发布状态分开显示 |
| 文件 | 实际转换结果的文件树和筛选；显示源／目标的一致、空目录省略或核对失败状态；选择文件后查看最终固定 SVN 快照与生成 Git 结果的并排文本预览，二进制显示摘要 |
| 历史 | 转换后的完整提交列表、源 SVN 修订号到 Git 提交号的对应，以及每条生成提交的差异；作者映射可在预检后编辑，占位邮箱会明确标记 |
| 差异与限制 | 单独列出空目录、属性、忽略规则、外部引用等处理结果，区分计划内转换、经用户选择的省略和阻断问题；不能把未核对项归入一致 |

文件核对的基准是源固定修订，不是空的目标远端；不能把所有文件都标成“新增”来替代转换正确性检查。文本可查看具体内容；二进制显示大小及内容校验摘要；目录、符号链接和可执行位按类型展示。大 blob 使用临时文件与分块摘要核对，不受普通命令输出的 16 MiB 内存保护限制；任何未核对对象仍会阻断预览和发布。

预览底部提供“返回调整”“保留本地结果”和“发布到目标 Git”。核对未完成或存在阻断问题时，不允许发布。用户返回修改范围、作者映射、历史模式等转换参数后，旧预览失效，需重新生成；不能沿用旧结果的确认状态。

发布绑定预览对应的源修订、转换策略、结果清单和目标提交／引用。发布前再次核对本地结果未变、目标仍满足计划；有变化时返回核对并更新预览。来源服务器后来新增提交时保持本次固定范围，提示截止修订，不静默替换已预览内容。 SVN 修订号在全仓库递增，因此所选目录最后一次变更可以早于截止修订；仅导入该目录真实发生的提交，不为对齐截止版本添加虚构历史。进入、浏览或退出预览均不写入目标远端。

## 3. 历史保留与转换差异

下表区分当前首版和后续方向；每个适配器仍须通过预检决定实际可用模式。

| 转换方向 | 历史处理目标 | 需要明确的限制 |
| --- | --- | --- |
| SVN → Git | **已实现**：导入所选目录的可读取线性历史或一个固定快照，保留文件变化、作者、作者时间与说明，并保存 SVN 修订到 Git 提交的映射 | Git 生成新的提交号；Git 的 committer 时间是迁移生成时间；SVN 的复制／合并、目录属性与空目录没有完全相同的 Git 表达 |
| Git → Git | 未重写时保留所选分支／标签可达的提交对象和父子关系 | 仓库托管平台的 issue、PR、权限、钩子不属于 Git 对象；LFS 和子模块内容需另行处理 |
| Git → SVN | 按能力重放指定历史或导入单个代码快照 | 合并图不能原样表示为 SVN 线性修订；原作者和日期的写入受服务器修订属性权限限制 |
| SVN → SVN | 有相应访问与修订属性权限时评估 dump/load 或镜像 | 普通检出／提交权限不保证能恢复原历史；指定子目录的路径重写、复制来源及授权范围需预检 |

SVN → Git 首版以所选目录的一条可读取线性历史为基础。`trunk/branches/tags` 整库转换需要显式路径映射，不能把每个普通目录自动认作 Git 分支或标签。关闭“包含复制前历史”时使用 `svn log --stop-on-copy`，保留固定 peg 和修订分页；开启时沿目录复制关系追溯。目录改名／复制的祖先历史只有在该路径可连续导出时才导入；任一修订无法导出会停止，不会跳过后伪造完整历史。后续补迁始终读取上次迁移节点之后的连续历史，不受这个初次范围开关限制。旧检查点缺少此选项时按原来的“包含复制前历史”恢复，不静默缩小已确认范围。

作者映射允许把 SVN 登录名对应到 Git 姓名和邮箱。SVN 本身没有提供的邮箱不能猜测成真实邮箱；使用占位值时需要在计划和结果中明确标记。原提交时间作为 Git 作者时间保留，迁移生成时间与原时间分别说明。

作者映射按“SVN 账号／Git 提交人／邮箱名称／邮箱后缀”编辑。普通 SVN 账号默认作为邮箱名称，没有配置真实后缀时使用明确的 `authors.invalid` 占位域名。邮箱后缀支持添加、选择和设置默认值；作者映射可主动保存，开始生成预览时也会保存。之后预检自动回填同一 SVN 服务端的已存映射。“设置 → 作者通讯录”集中查看、搜索、编辑及删除映射，并管理邮箱后缀。不同协议、主机或端口的来源独立保存；本地 `file://` 来源按路径隔离，不将 URL 中的登录凭据写入通讯录。

### 3.1 迁移进度与性能

只读预检立即进入独立进度页面，显示当前正在核对本地状态、目标 Git 或 SVN 历史，并提供取消入口。转换时将“已完成修订数／总数／当前修订”与工具当前阶段分开显示；进入 Git 对象写入或核对阶段时清除上一阶段的传输速度。长时间没有新输出时明确显示等待状态及取消入口，不用模拟心跳、虚构百分比或固定预计时间代替实际工作量。

迁移预检只读取实际使用的修订号、作者、时间和提交说明，不再附带每个修订的全部变更路径。关闭复制前历史可以缩小初次迁移范围；保留完整历史时仍逐个修订生成对应 Git 提交，不通过跳过版本换取速度。

Git 目标适配器批量计算文件对象、分批读取真实对象内容，避免每个文件单独启动 Git。批次受参数长度、对象数量和内容大小限制，仍保留二进制、可执行位、符号链接以及每个修订的独立内容核对。每个修订通过核对后清理不再需要的旧临时文件树；失败时保留当前隔离结果供排查。

Git 的已验证导入会话在首次建立对象映射后，复用未变化文件对应的对象，仅为变化内容写入和读取 blob；工作树也只更新变化路径。每个修订仍核对完整 Git 树的路径、类型、权限和对象 ID，新对象读取实际字节并比较 SHA-256。两个初次迁移流程只在最终修订完整导出目标并逐文件核对，避免中间版本反复导出整棵 Git 树。新目录迁移的检查点保存已核对源清单，恢复时重新导出实际 Git 树验证；旧版检查点仍可读取。补迁保留三方差异应用，不用 SVN 全树覆盖 Git 的独立修改。

初次迁移在已验证目标支持对象复用时，自动预取 SVN 快照，与当前版本的 Git 写入及核对重叠执行。新目录迁移预取一份；当前工作副本初迁最多使用三个独立 SVN 缓存并行预取，待消费快照也最多三份，每个缓存自身仍按修订串行更新。Git 提交、逐版本内容核对和检查点仍按原计划顺序推进。预取记录不会增加已完成修订数；取消或失败会先取消并等待后台任务停止，再清理来源缓存。普通适配器兼容流程和当前工作副本补迁不启用这一预取路径。

固定修订的历史节点只读查询使用 120 秒时限，超时自动重试一次；认证、证书、解析错误及取消不会触发重试。隔离工作副本的本地节点、版本和完整状态核验使用 120 秒时限。错误会显示相关修订与阶段；不会重放整个快照导出、switch 或 checkout。

SVN 每个修订固定 peg 的历史节点查询与隔离缓存的检出／切换并发，最多同时执行一个只读查询和一次缓存更新；两者成功后仍核对 URL、UUID、精确修订和工作副本状态。Git 提交后的提交号及父级使用一次查询读取，减少逐修订的进程启动。并发收益取决于可重叠的网络等待和本地处理时间，不改变最终内容核对要求。

SVN 来源使用一次转换独享的修订会话，禁止在逐修订循环中重复从远端 `export` 整棵目录。新目录迁移首次检出需要的起始修订；当前工作副本首次迁移可只读复制已核对的本地干净基线到隔离缓存。后续以固定的 `URL@anchor` 和目标修订增量切换该缓存，再从本地整理快照，不重新下载未变更文件。使用固定 peg 的 `switch` 而非只对旧 URL 执行 `update`，使复制、目录改名之前的祖先历史仍指向正确路径。

`.svn` 保存工作副本的元数据和当前 BASE 原文，不等同于完整历史对象库；`svn log -v` 提供作者、时间、说明和变更路径，不包含全部历史文件字节。缺失的历史内容仍需联网增量取得。补迁时 SVN 工作区可能包含 Git 演进产生的本地差异，因此不复制该目录作为干净基线，而是在隔离缓存中从上次锚点开始。来源会话结束或失败后清理缓存，恢复使用新的缓存，不信任上次被中断的工作副本。

每个修订仍在本地生成 Git 提交并核对全树，大型仓库的总耗时取决于实际变更量、历史数量、文件规模、磁盘和服务器响应。增量读取不会把“保留历史”降级为单快照，也不省略任何修订的内容校验。进度分别标明首次下载、增量获取和本地整理；本地整理不沿用上一阶段的下载速度。

增量读取的隔离测试和网络字节对照见[增量迁移验收](verification/migration-incremental/README.md)。下载量减少不能直接当作完整转换耗时同比下降。

空目录不会作为 Git 目录对象保留，会在预览中列为省略；SVN 自定义属性、目录属性与 `svn:externals` 只提示限制，不会自动转换。可执行位和符号链接按导出结果重建并核对。快照模式只产生一个新的初始提交，不伪装成原有完整历史。

首版不依赖 `git svn`：它通过现有 SVN 适配器读取固定修订、增量维护隔离工作副本并生成本地快照，再交给 Git 目标适配器生成对象。SVN 读取沿用既有 TLS 自动兼容路径，TLS 模式在会话首次联网时探测一次，写命令不自动重放；本轮没有把真实旧 TLS 服务作为迁移验收环境。不得降低全局 TLS 或绕过证书检查。

## 4. 独立契约与执行边界

当前已接入的核心契约如下：

- `MigrationMode / MigrationSourcePlan / MigrationPlan`：源路径、固定修订、目标、本地新目录、历史模式和作者映射；计划固定本次来源范围。
- `RepositoryMigrationSourceProvider / TargetProvider`：分别承担只读导出、目标格式生成与发布；工具命令、解析及认证仍在适配器内。组合专属的转换器可补充处理历史拓扑，不强迫所有工具都模拟 Git。
- `RepositoryMigrationSnapshotSession`：每次转换独享的来源缓存与按修订快照接口。业务层分配、清理隔离路径；SVN 适配器处理检出、增量切换和本地整理，其他来源保留单快照接口的兼容实现。
- `RepositoryVerifiedMigrationTargetProvider / RepositoryVerifiedMigrationSession`：目标可选的已验证对象复用能力。业务层提供来源实际字节清单，目标适配器实现完整树核对和对象复用；不支持该能力的目标仍逐修订导出核对。
- `RepositoryMigrationService`：编排预检、独立暂存、转换、核对、发布和中断恢复；界面只接收结构化进度与结果。
- `MigrationPreview / Manifest`：记录固定来源、策略、源修订到目标提交的映射、代码核对结果、警告及远端发布结果。
- `WorkingCopyMigration`：独立描述当前 SVN 工作副本的接管、来源身份与范围标记、累计映射、隔离三方应用和确认后的原地 Git 安装／快进；不复用初始化或普通提交语义。

迁移不复用“未受管控目录初始化”的单选状态，也不复用工作区按文件提交的请求。现有获取流程的独立暂存、凭据脱敏、取消与进度模型可以复用，但迁移本地转换成功和目标发布成功必须分别表达。

目标复核发现任何已有分支、标签或初始提交时，首个空仓库流程停止。最终写入还需使用目标适配器提供的创建条件保护，避免预检后的并发变更被覆盖；服务端无法提供同等级条件时必须暴露这一限制。拒绝强制覆盖已有引用。

检查点和清单只保存非敏感信息；恢复时需重新提供来源凭据。中断后保留隔离结果，只有来源固定修订、转换策略与已生成对象均核对一致时才允许继续。若提交已经产生但尚未完成对象树核对，恢复会拒绝继续并要求重新预检，避免重复追加同一修订。发布超时或取消可能已经改变远端，先读回引用核对，不能自动重推，也不能自动回滚远端。

### 后台运行与大文件

迁移窗口右上角的“后台运行”只收起窗口，转换继续执行。工具栏保留旋转标记和已完成/总修订数；点击恢复原来的迁移路径、预览页签和选择。完成或出错后保留可查看提示，明确关闭迁移窗口才清除。后台期间可以查看当前文件和历史、切换仓库；涉及迁移来源或目标目录及其父子目录的写入口暂时锁定，其他独立仓库仍可操作。退出保护仍把后台迁移计为进行中的任务。

超过内存批量预算的 Git blob 改为排他临时文件落盘、按 1 MiB 分块 SHA-256 校验，最终导出也走大文件路径；普通命令输出的 16 MiB 保护不变。每个 blob 以已知对象大小约束实际输出，不再用 16 MiB 单文件上限拒绝历史文件。工作副本最终核对同样分块读取；失败提示包含路径、大小和修订上下文。

新版“当前工作副本”初次迁移每完成一条已核对提交，就保存 `checkpoint.json`。同一计划失败后可以重试；关闭应用后，“继续已有迁移…”会列出保留任务，也可手动选择保留目录或检查点。恢复先沿用原计划、固定截止修订、作者映射和已经完成的 Git 提交，只核对已完成末端的对象与 SVN 快照，不重新转换已完成历史；未完成任务从下一条修订续跑。原范围完成后，历史模式自动检查当前 SVN 工作副本 BASE 是否已经前进；若所选目录有后续提交，只读取原截止点之后、本地 BASE 以内的连续历史并追加，旧 Git 提交 ID、作者和首次接管节点保持不变。预览也提供“检查并补入后续提交”入口。

追加范围先原子保存到检查点，再转换新增部分。检查点同时保留已核对末端实际使用的截止修订；即使首条新提交尚未产生就中断，重启后仍能核对旧末端、从新增范围继续。混合修订按本地节点已到达的最高 BASE 固定追加范围，最终仍逐路径核对当前目录。界面分别显示初始 BASE、本次截至版本和实际末次目录提交；SVN 全仓库版本前进但所选目录没有变更时，不伪造提交，也不自动迁入高于本地已到达版本的服务端新版本。

恢复预览不重新要求原工作副本满足首次迁移的单一 BASE 条件；后续形成混合修订或本地修改，不会废弃已生成历史。恢复使用独立 SVN 快照缓存，不把变化后的工作副本当作固定来源。应用到原目录前仍检查来源身份、受版本控制文件状态、布局、Git 基线、远端引用和固定快照内容；原目录内容已变化时保留恢复预览并阻止应用，可重新核对，无需重新转换历史。若隔离 Git 已产生未核对的额外提交或对象树被修改，仍拒绝自动续跑。补迁暂不支持断点恢复；旧版本没有检查点的临时目录保留，但不能仅凭提交说明自动接管。

## 5. 隔离验收

开发和自动验证只使用临时 Git 裸仓库、本地 SVN 服务及模拟故障，不对用户业务仓库执行迁移、提交或推送；实际执行记录见[原生验证记录](native-verification.md)，本文不代替该记录声明测试结论。

- SVN 多作者、多修订、增删改、二进制、中文／空格路径，核对历史条数、作者时间、说明和最终代码。
- 指定子目录及复制／改名历史，确认范围外文件不混入；无权读取的祖先明确失败或由用户选择快照。
- SVN 属性、空目录、符号链接、可执行位、externals，逐项检查报告与实际转换一致。
- 长历史分页与断点、取消／重试、读取中断、磁盘不足，确认不静默截断历史、不污染原工作副本。
- 非空 Git 目标、预检后目标变化、无推送权限、分支保护、推送响应丢失，确认无覆盖且可核对最终状态。
- 只迁移代码的显式选择、未提交修改提示、凭据脱敏、旧 TLS 读取路径以及原生界面进度与结果预览。
- 预览的文件树、差异、完整分页历史与实际生成仓库一致；源修订／目标提交映射可定位，预计数量与已核对数量不混用，二进制和未核对项不会显示为文本一致。
- 修改转换参数使旧预览失效；核对失败阻止发布；预览后本地生成结果或目标远端变化可被检测，实际发布内容与最终预览一致；只查看或退出预览不产生远端写入。
