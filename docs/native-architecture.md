# RepHub 原生客户端架构与视觉约束

状态：2026-10-12。已建立 Swift Package 原生工程、读取工作台、仓库获取、更新、按文件提交、初始化、仓库管理和首版 SVN → 空 Git 迁移；本文件同时保留完整目标约束，未列入下方“当前实现”的内容仍是后续计划。文中保留的“首轮”“后续”措辞如与“当前实现”或[初始化、管理与关联工作副本](repository-management.md)冲突，只作为需求演进记录，不表示当前能力缺失。

当前实现：独立契约模块、Git / SVN 适配器、目录双绑定和独立目录关联、状态 / 差异 / 分页历史读取、Git 父子图、主题系统及原生设置。历史、SVN 修订和文件历史统一先读取最近 150 条，按各自已读锚点继续读取更早记录；刷新从首批重新开始，标题、作者和日期范围筛选只作用于已加载结果，并提供匹配计数、清空筛选和完整修订号复制。工具通过参数数组运行，支持超时和取消。已有仓库支持 Git fetch / 快进更新及 SVN update，单选目标并刷新全部绑定。统一“打开仓库”入口支持本地目录、Git 克隆和 SVN 浏览后检出指定子目录。未受管理目录可单选 Git 初始化，或执行 SVN 导入、校验检出和原目录备份发布。Git 的远端/本地身份、独立推送、按文件暂存、分支/合并、冲突标记与版本比较由单独管理契约提供；SVN 只提供其真实可支持的冲突标记与修订比较。SVN 新增目录节点以非递归范围提交，比较可只读呈现目录节点自身属性变化。项目前台期间可监控本地状态，退出应用即停止；自动轮询只在前台空闲时执行，手动检查可在后台运行但同样受 busy guard 保护，并保存最近检查和错误状态；分栏尺寸独立保存。SVN 在默认连接出现协议握手兼容错误时自动尝试旧 TLS，成功后按 HTTPS 主机与端口短期缓存，无需界面配置；写入前只读探测，更新命令仅执行一次。SVN 使用本机已有工具与认证配置，也可输入仅在本次应用会话使用的用户名和密码；密码通过内存标准输入管道传递，不进入命令行参数、配置文件或普通日志。不降低全局 TLS 或绕过证书错误。

## 1. 版本控制独立分层

运行时：原生界面 → 工作区业务 → 版本控制契约 → Git／SVN／其他适配器 → 工具执行基础设施。

编译依赖与运行时调用区分：适配器依赖契约，契约不依赖任何具体适配器；应用入口负责注册实现和注入依赖。

| 建议模块 | 职责与依赖边界 |
| --- | --- |
| VersionControlCore | 独立 Swift 模块，定义领域模型、能力接口、错误和操作结果；不依赖 SwiftUI、进程命令或具体工具 |
| GitAdapter / SVNAdapter | 实现契约，构造命令并解析输出，保留工具专属语义；依赖契约和基础设施 |
| RepositoryApplication | 仓库识别、操作计划、共享路径协调、结果恢复及刷新；只依赖工具契约 |
| DesignSystem | 应用主题、代码主题、外观解析和原生组件样式；不依赖仓库工具或 AI |
| RepHubUI | 工作区、历史、设置与 AI 界面；调用业务服务，不运行 CLI |
| RepHubApp | 启动、窗口、设置持久化和依赖组装；仅组装入口引用具体适配器 |

第一轮使用静态适配器注册表，不要求动态插件加载。扩展新工具时不修改现有业务和视图中的工具类型分支。

### 契约与能力

- `VersionControlProvider` 提供类型标识、显示名、可用性与目录检测入口。注册表可返回多个匹配绑定。
- `RepositoryHistoryProvider` 独立提供单文件历史、历史路径差异及同步状态；`RepositoryHistoryPagingProvider` 在其上扩展仓库及文件历史分页，请求携带每页条数和不透明游标，具体适配器负责固定起点、追溯和续读。`FileHistoryEntry` 保留适配器追溯所需的路径和锚点。业务层校验相对路径并单独保留同步读取错误，UI 不解析命令输出。Git 保留分支上游语义，SVN 保留工作副本 BASE 与混合修订语义。
- `RepositoryOperationProvider` 单独定义异步写操作入口，使用 `RepositoryOperationKind`、阶段进度与 `RepositoryOperationResult`；界面不导入 Git / SVN 模块。`RepositoryService` 负责同实例操作互斥、目标复核、取消后脱离取消上下文刷新所有绑定。
- `RepositoryAcquisitionProvider` 独立提供新工作副本获取和可选的远端目录浏览能力。Git 克隆整个仓库，SVN 按需浏览单层目录并检出选定子目录；界面按能力展示控件。业务层与更新共享写互斥，先在目标父目录的独立暂存目录中获取，成功后移至指定的新目录。已有文件、目录和悬空链接均拒绝覆盖；取消或失败保留部分下载并报告具体位置。SVN 检出先只读探测 TLS，随后只执行一次检出，不递归获取 externals。
- `RepositorySetupProvider` 接收单选的 `RepositorySetupRequest`。Git 仅初始化本地仓库；SVN 仅导入到明确且尚不存在的远端目录，完成检出和内容核对后才以备份替换原目录。初始化业务层在写入前重新识别全部来源，检测故障、嵌套元数据和已有工作副本均拒绝继续。
- `RepositoryManagementProvider` 与 `RepositoryComparisonProvider` 独立承载远端/身份、push、暂存、分支、冲突解决与任意两版本比较。业务层以管理状态令牌、当前绑定和能力复核阻止过期请求；每次写操作后重新识别并读取全部关联来源。
- `RepositoryBinding` 包含实际工作副本根目录、在工作区内的覆盖范围、远端信息和可用能力。一个工作区允许多个绑定；嵌套和共管不能只用一个仓库类型枚举表示。
- 检测结果区分已识别、确认未管理、工具缺失、权限不足、元数据损坏与未知错误；检测失败不能降级为“未管理”。
- 按状态、差异、分页历史、工作副本获取／初始化、更新和提交拆分能力。暂存、推送、分支和提交拓扑为可选能力；根据绑定及工具版本判定是否可用。
- 修订标识、比较基准、路径状态、文本／二进制差异、提交父子关系使用结构化模型。SVN 不伪造 Git 暂存区或 Git Graph。
- `RepositoryFileContentProvider` 提供固定修订下的原始文件读取，SVN 另保留文件历史 peg 锚点；应用层生成带生命周期管理的私有临时文档快照，界面仅交给 Quick Look。缺失、失败和超限分别处理，历史预览不回退到工作区。
- `RemoteRepositoryHistoryStore` 独立保存远端获取的地址历史与账号元数据；密码通过 `RepositoryCredentialStore` 契约读写，由入口注入 `KeychainRepositoryCredentialStore`。账号以标准化协议、主机、端口隔离，秘密不进入 UserDefaults。自动填充使用独立请求令牌，过期读取不得覆盖手动输入或新服务器；成功连接后才记忆凭据，历史选择不触发网络请求。
- 命令参数、输出解析、退出码、工具路径和 TLS 兼容配置封装在适配器／基础设施；UI 不读取 stdout 判断成功。旧 TLS 自动回退只作用于对应 HTTPS 端点的只读命令，缓存不持久化；超时、取消、认证及证书错误不触发回退。未来写操作不能直接套用只读命令的重试逻辑。
- 操作提供异步进度、取消、超时和结构化结果。成功、失败、取消、结果未知分别表达；网络超时后先核实实际结果再重试。
- 获取和更新共享结构化实时进度：阶段名称、可选的阶段百分比、详情及文件／信息记录。Git 提供对象传输和检出阶段，SVN 提供实际输出的路径状态，不假定每种工具都有逐文件下载量或总百分比。`CommandRunner` 仅在订阅进度时增量读取 stdout/stderr，适配器负责解析；业务层脱敏后交给 UI。界面只保留最近 250 条记录，显示累计记录数、已用时间和最后活动时间，支持跟随最新与取消。
- 同目录及重叠目录的写操作由业务层协调，完成后刷新所有受影响绑定；多目标提交分别保存结果，不重复执行已成功目标。
- `WorkspaceLinkStore` 只保存主目录到关联本地工作副本的规范化路径，不保存远端或凭据。关联目录必须独立识别成功；移除关联只删除本地记录，不删除工作副本。`WorkspaceMonitor` 仅在应用前台、空闲且未执行仓库写操作时检查本地状态，不做远端同步，也不在应用退出后运行。

### 按文件提交

- `RepositoryCommitProvider` 独立提供只读准备、单文件最终差异及执行入口。准备结果包含比较基准、文件快照及限制原因；界面按目标独立选择文件、预览和填写多行说明。
- 所有目标通过只读预检后，按 Git、SVN 顺序执行，共享获取／更新的写互斥。普通失败保留结果并继续；取消或结果未知停止后续目标。无自动重试，不把双边提交视为事务。
- Git 以所选文件当前工作区版本构造临时索引。持有真实索引锁，提交完成后只同步所选路径的索引条目，保留未选暂存内容。提交仅在本地，不推送；合并中、冲突、子模块和外部过滤器等无法安全处理的范围会被限制。
- SVN 提交使用显式路径及 `--depth empty`；必要的新父目录也只按 empty 加入。文件内容、属性、状态和 BASE 在执行前再次复核。目录递归删除、复制／移动等关联范围暂不支持。先只读确定 TLS 模式，再执行一次 commit；命令启动后未取得可信修订号时标记待核实。
- 完成后刷新全部绑定，结果窗口分别显示修订号和详情，可进入对应来源历史定位提交。准备和预览不会暂存文件；本地 SVN add 只在最终提交操作内执行，提交失败可能留下已调度新增状态。

### 初始化与提交不能共用多选状态

`RepositorySetupRequest` 只接受一个 `providerID`，对应 Git 或 SVN 单选；`RepositoryCommitRequest` 按已存在的绑定分别构造，批次可包含多个目标。已有双管控目录继续识别。SVN 接入按真实导入／检出流程定义，不实现虚构的本地 `svn init`。

### 仓库迁移（两种 SVN → Git 模式已实现）

迁移是独立于初始化、工作副本获取和按文件提交的流程。当前实现 SVN 指定目录到空 Git 仓库，并支持可读取线性历史或用户明确选择的快照；具体约束见[仓库迁移设计](repository-migration.md)。`RepositoryMigrationSourceProvider` 与 `RepositoryMigrationTargetProvider` 分别负责只读导出、目标对象生成和发布，`RepositoryMigrationService` 编排固定修订、独立暂存、逐修订对象树核对、检查点和结果记录。界面只接收结构化进度与预览，不执行转换命令，也不能把不支持的历史模式静默替换为快照。

本地转换与远端发布分别记录状态。源工作副本保持不动，空目标在发布前复核且以目标分支尚不存在作为发布条件；已有历史的合并不进入首个流程，不允许覆盖已有引用。作者映射可编辑；SVN 未提供邮箱时使用明确的占位邮箱，原提交时间保留为 Git 作者时间。预览显示最终文件树、源／目标内容、生成提交差异和修订映射；单个 blob 超过 16 MiB 会阻断对象树核对。检查点不保存凭据，恢复需重新输入；如果提交已产生但未核对，恢复会拒绝继续并要求重新预检。SVN 读取沿用适配器的 TLS 和认证能力，但真实旧 TLS 服务迁移仍需独立验证。

`WorkingCopyMigration` 是另一条契约路径，不能把接管行为塞入初始化或普通提交。它读取当前 SVN 工作副本的元数据，首次固定本地 BASE，后续补迁固定远端 HEAD；记录源 URL、UUID、历史起点、BASE／接管点、截止修订和累计映射，每个生成提交用 trailers 重复标记这些来源边界，补迁前复核远端 UUID 与末端提交标记。首次接管拒绝已有 Git、受管修改、混合修订、稀疏／switched 工作副本和 externals，保留普通未跟踪文件且不自动更新或提交 SVN。补迁前业务层复核 Git 已跟踪工作区干净和远端等于本地 `HEAD`；Git 独立修改的三方 cherry-pick 与冲突只在内部隔离预览目录计算。用户确认后才原地安装 `.git` 或快进并推送。该路径不承诺跨重启恢复未应用的新预览；本地已应用但远端未发布时保留 `origin`，由现有仓库管理的 Git 推送继续。旧空目标模式的检查点恢复仍独立保留，两种模式都不形成持续双向同步。两种模式的自动化及原生流程已在临时仓库验收，实际结果见[原生验证记录](native-verification.md)。

### AI 独立分层

- `AICore` 定义连接、场景、所选差异快照、进度、提供者及凭据契约；不依赖 SwiftUI、HTTP、进程或具体 Git/SVN 实现。
- `AIApplication` 持久化非密钥配置，编排提供者选择、范围上限、取消和超时。`AIAdapters` 分别实现 Chat Completions、OpenAI Responses、Anthropic Messages、本机 Codex/Claude 及钥匙串，由应用入口统一组装；协议选择不由 API 地址猜测。
- 厂商预设不新增协议类型。`AIModelCatalogProvider` 独立查询模型元数据，`AIExecutionRequest.effectiveModel` 根据场景与当前连接解析模型；跨连接执行不会沿用其他厂商的场景模型。
- `AIProgress.usage` 是当前请求的完整累计快照，由适配器按实际协议归一化。`AIService` 在终态将最新快照记录至 `AIUsageStore`，不重复相加、不估算缺失值；统计存储不含输入、输出和凭据。
- `RepositoryAIContextService` 只通过版本控制业务读取所选文件，前后复核基准和文件指纹。AI 面板保存场景、连接、范围及内容快照；生成结束和填入前重新核对。
- 用户点击后才执行 AI；结果可编辑，AI 不能触发提交。Git/SVN 提交说明按目标独立保存。协议与 CLI 权限边界见 [AI 功能说明](ai.md)。

## 2. 三项独立的外观设置

| 设置 | 负责内容 | 建议默认行为 |
| --- | --- | --- |
| 应用主题 `AppThemeID` | 强调色、导航／面板层次、边界、控件状态、图表配色、材质 | 首版至少两套完整主题；默认按原设计稿的温润风格 |
| 日夜模式 `AppearancePreference` | 跟随系统、日间浅色、夜间深色 | 默认跟随系统；手动指定后不受系统切换覆盖 |
| 代码配色 `CodeThemeSelection` | 代码背景／前景、语法、行号、选中、搜索、增删和冲突 | 可固定配色，也可指定随有效外观切换的浅／深配色组合 |

设置入口建议为原生设置中的“外观”和“代码配色”。顶部 AI 审查右侧不恢复重复设置齿轮。

解析顺序：

1. 按日夜模式与系统外观得到有效的浅色或深色。
2. 取所选应用主题的对应变体。
3. 固定代码配色直接使用；自动代码配色按有效外观选择其浅／深版本。
4. 更新样式并独立保存偏好，不重建仓库会话或清空当前任务。

浅色应用配深色代码、深色应用配浅色代码都是有效组合。切换应用主题不改写代码主题选择；系统切换仅影响设为跟随的项目。

### 实现约束

- 页面使用语义样式，不零散写死颜色。应用主题和代码主题分别定义，强调色不能覆盖增删、语法和状态颜色。
- 代码主题完整覆盖普通文本、背景、关键字、字符串、数字、注释、类型、行号、选中、光标、当前行、搜索、增删和冲突；叠加选中和搜索后仍能辨认差异。
- 代码／差异区域有稳定底色，新增与删除同时保留符号、行号及状态文字，不只依赖颜色。
- 应用主题均提供浅／深变体，深色按原设计的层次配色，不简单反色。菜单、弹窗、提示和 Git Graph 一并适配。
- 即时切换并在重启后恢复；保留仓库、文件选择、历史筛选、滚动位置、提交草稿和进行中的 AI 任务。分栏尺寸按工作区、历史和差异区域分别持久化；窗口临时变窄时只压缩可见范围，不覆写保存值。
- 尊重减少动态效果和降低透明度设置；具体 Liquid Glass API 与系统版本回退在原生工程建立时验证。

- [历史原始设计稿](design/history-reference.png)

采用原稿的浅净、温润、轻玻璃导航和清晰代码区域，保留适度圆角与柔和交互。使用原生菜单、工具栏、分栏、表格和设置窗口；内容区不仿画系统菜单栏或窗口红黄绿按钮。分栏边界按当前窗口剩余空间计算，仅保留可见的最小区域；侧栏、详情和上下差异可拖动，窄栏内容不得溢出到相邻区域。

HTML 只用于核对操作流程，不复制其 CSS 配色、尺寸、阴影或网页组件作为正式视觉标准，也不将其嵌入原生窗口作为主界面。

### 当前布局约定（2026-10-13）

- 工作区表达当前工作副本，不承载历史列表：左侧是当前仓库的变更／全部文件树及提交文件勾选，中间是全高代码差异，右侧是可收起的提交检查器。检查器承载提交说明、AI 生成、已选 Git／SVN 目标、文件范围和提交动作；不再在底部放置历史。
- 冲突属于当前工作副本状态：更新或提交受阻时，在对应操作附近显示冲突数量、文件和进入冲突处理的入口；未解决冲突不作为可提交文件自动加入范围。Git 与 SVN 按各自真实冲突能力显示后续操作。
- 历史是独立主视图：左侧连续提交图和提交列表负责定位，右侧按摘要、变更文件树和所选文件差异组织详情。历史主视图不显示工作区提交草稿或全部文件树。
- 单文件历史使用独立全页范围，显示被追溯的路径和版本范围，提供返回仓库全部历史的入口；不复制仓库分支树或变更文件树，差异以并排阅读为主。适配器提供的改名前路径、SVN peg／修订锚点和分页游标必须原样经过业务层，不能由视图猜测。
- 切换工作区、仓库历史与单文件历史只改变阅读范围。工作区文件选择、提交草稿、历史选择、滚动位置和已展开节点应分别保留；已缓存差异不因 TAB 往返重读。仅标准化根目录完全相同的 Git／SVN 共享提交勾选意图，独立根目录（包括嵌套目录和名称前缀相同的兄弟目录）隔离；刷新删除消失路径，不自动选择新增路径。

## 4. 首轮交付与验收

- 建立独立模块、原生窗口和可注入工具接口，完成 Git/SVN 识别及读取的纵向流程；模拟适配器只用于预览与隔离验证，真实能力通过实际目录验证。
- 在原生骨架阶段接入主题、代码配色和日夜模式，避免后续逐页修改固定颜色。
- 替换适配器时界面与业务不导入具体实现；不支持的能力有明确状态。
- 每个应用主题检查浅／深／跟随系统模式，另检查固定浅代码、固定深代码和自动代码配色；系统切换不覆盖固定设置。
- 工作区和历史对照原始设计稿，检查差异、选中、搜索、冲突、语法高亮、Git Graph、弹窗及辅助功能偏好。
- 切换后继续操作并重启，确认偏好保留，切换不清空工作区和任务状态。

## 5. 追溯与本地整理扩展

`VersionControlCore` 通过可选协议分别声明逐行追溯、冲突编辑、搁置、忽略规则和 Git 局部提交，不把 Git 特性强加给 SVN。`RepositoryApplication` 校验绑定、路径、预览状态与能力；所有写操作共享 `RepositoryService` 的互斥状态。适配器负责工具语义、固定修订及内容指纹，原生面板仅操作类型化模型。

迁移源监控复用 `WorkingCopyMigrationService`，先核对本地迁移记录及源身份，再只读查询对应 SVN 路径的最新修订。前台空闲时检查，切换／关闭工作区取消旧任务；提醒仅引导现有补迁预览，不自动同步。

AI 问题定位由发送快照验证相对路径和新侧行号，跳转前再次核对快照。忽略空白和行内强调属于展示层，不改写适配器原始补丁。新增面板的操作和限制见[代码追溯、审查与本地整理](advanced-workflows.md)。
