# 文件历史与提交同步状态

## 操作入口

- 工作区文件列表右键“查看文件历史”。
- 历史页右侧变更文件右键“查看文件历史”，从所选提交追溯，包含该提交；可用于已经删除的文件。
- 历史列表上方“文件历史”图标选择当前工作副本中的本地文件，也适用于没有本地修改的已管文件；沿用当前历史分支、标签或文件锚点，未指定时从 HEAD 开始。

文件模式显示文件路径和历史锚点，点击提交查看该文件当次差异；“显示全部历史”回到仓库记录并保留原分支筛选。刷新保留文件范围与选中提交，回到工作区则恢复本地变更差异。

文件历史独立查询，不从仓库历史中筛选。初始读取最近 150 条；点击底部“加载更早”或滚动至末尾继续读取更早记录，刷新从首批重新读取。Git 从当前 HEAD 或所选历史修订开始并追溯重命名；SVN 使用路径与 peg revision 沿复制、移动关系追溯。文件历史暂不画 Git Graph，以免把缺省隐藏的父提交画成完整拓扑。历史搜索只匹配已读取的文件记录，不会隐式扫描全部服务端历史。

## 状态含义

| 状态 | Git | SVN |
| --- | --- | --- |
| 待更新 | 当前分支实际上游可达、HEAD 不可达 | 当前显示范围内，修订晚于本地 BASE |
| 待推送 | HEAD 可达、实际上游不可达 | 不适用，SVN 提交直接写服务端 |
| 已同步 | HEAD 与上游均可达；详情展示，列表不重复标记 | 修订不晚于可确认的 BASE |
| 需核对 | 列表提交超出有界拓扑判断范围 | 混合 BASE 中无法确定的记录，或切换 / 稀疏目录 |

Git 计数始终针对当前分支与其真实配置的上游，文件筛选或其他分支筛选不会改变比较对象。其他分支独有的记录不会被误标为待推送。未配置可用上游、游离 HEAD、以上游本地分支代替远端的情况显示未知，不显示伪造的零计数。

Git 判断基于本机已经获取的远端引用，**不会自动联网 fetch**。需要最新远端状态时，通过顶部“更新 → 获取远端”刷新；普通刷新只重新读取现有引用。此功能只展示待推送状态，推送执行尚未接入。大仓库总 ahead/behind 计数不受列表上限影响，行状态最多追溯 5,000 条，无法确认的行显示需核对。

SVN 历史读取远端 HEAD，结合本地 `svnversion` 和 `svn info` 判断。统一 BASE 可直接比较；混合 rA:rB 时，晚于 rB 为待更新，不晚于 rA 可确认已更新，中间范围需核对。单文件使用自身 BASE，避免误用目录修订。SVN 数量限定为当前读取的历史范围，不冒充全部服务端待更新数量。已删除或尚未存在于本地的历史路径仍可阅读记录与差异，但同步状态读取可能显示原因说明。

## 模块和测试边界

核心契约在 `VersionControlCore/RepositoryHistory.swift`，分页扩展在 `HistoryPagination.swift`；命令和解析只在 Git / SVN 适配器，`RepositoryService` 负责路径范围校验和错误隔离。文件历史读取失败显示具体错误，同步信息失败不丢弃已经读到的记录。现有 SVN TLS 自动兼容路径继续用于远端只读命令。

分页会固定首次读取的 Git 提交或 SVN peg revision，避免翻页期间新增提交导致页边界漂移。Git 单文件历史为保留跨改名与合并的完整追溯，每次从固定起点读取截至本页末尾的元数据前缀再切片；不提前读取全部历史或全部差异，但越靠后的文件历史页会重复解析先前元数据。仓库历史和 SVN 历史按各自游标直接续读。

定向自动化测试只创建临时本地 Git bare / file:// SVN 仓库，使用隔离 HOME；不以 EFB 或其他业务仓库作为样本。`scripts/create-history-fixtures.py` 提供同样隔离的原生界面验收数据，不覆盖已有目录。
