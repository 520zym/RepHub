# RepHub · Canvas 全页面设计提案

日期：2026-10-22。状态：**设计提案，未实现**。本组图沿用已选定的「C · 流光」方向，把工作区、历史、仓库获取、提交核对、冲突、AI、设置与迁移统一到同一套组件语言。

> 所有图片都是 HTML/CSS 渲染的设计稿，使用示意仓库与示意数据。没有修改 SwiftUI 界面，也没有对任何仓库执行写操作。HTML 只作为评审载体，不替代 2026-10-16 已确认的 `soft-surfaces` 视觉基准；正式落地前仍需按原生窗口做验收。

## 设计原则

1. **一个页面只有一个主动作。** 主按钮永远是靛蓝；取消、返回、关闭都退到安静层级。危险或远端写操作在按钮旁明确说明。
2. **用面与留白分区，不用分割线。** 主页面是冷雾底色 + 20 圆角白卡；弹窗是白色面板 + 70 点标题区 + 66 点底部操作区。
3. **代码阅读优先。** 双行号、等宽字体、19 点左右行高；差异行是矩形，不跟随卡片的圆角；增删同时用底色、符号和文字。
4. **状态不只靠颜色。** 成功、失败、待推送、冲突、未映射都同时有文字或图标。
5. **保留 Git / SVN 差异。** 不把 Git 的拉取、推送、暂存强套给 SVN；提交窗口按目标分开显示说明与范围。
6. **不发明状态。** 目录页不伪造下载速度，提交结果不自动重试；未知、读取失败、取消都保留真实语义。

## 页面清单

### 主页面

- [工作区](01-workspace.png)：沿用已确认的 C 方案。左侧变更树、中央统一差异、右侧三步提交；顶部审阅进度和差异内前后文件构成浏览节奏。
- [提交历史](02-history.png)：左侧提交记录 + 双色 Git 图；右上提交摘要与文件，底部大差异。待推送、分支、哈希都在同一视线内。
- [文件历史](03-file-history.png)：单一文件的提交列表与全高差异；页面头保留「历史 / 追溯」切换。
- [开始 / 最近仓库](04-welcome.png)：无仓库时的入口页。左侧本地、克隆、检出，右侧最近记录；不是营销页。

### 仓库获取

- [打开仓库 · 本地](05-open-local.png)：本地文件夹选择 + 最近记录；Git、SVN、共管目录在同一入口。
- [远程获取 · 选择目录](06-acquire-browse.png)：SVN 四步向导的第二页；左侧步骤、中间目录表、右侧检出摘要。
- [远程获取流程板](14-acquisition-flow.png)：连接、本地位置、确认检出、真实传输中四个状态。
- 传输页不预填速度；只有真实传输开始后才显示进度、当前文件和速率。

### 提交、更新与冲突

- [提交前核对](07-commit-preflight.png)：双目标（Git / SVN）切换，文件范围、差异预览、每个目标独立说明，以及提交前的最终按钮。
- [仓库管理 · 推送](12-management.png)：远端、目标分支、上游设置、推送预览与本地领先状态。分支、暂存、冲突、比较、设置复用同一页签结构。
- [处理内容冲突](08-conflict-editor.png)：基准 / 本地 / 传入三栏 + 最终结果；冲突块可逐个采用，保存只标记已解决。
- [更新工作区](15-utility-dialogs.png)：更新/获取的二选一、版本控制来源、当前分支与本地目录，明示快进或冲突行为。

### AI、设置与迁移

- [AI 代码审查](09-ai-review.png)：左侧文件范围与场景/连接，右侧可定位问题、摘要和 token 用量；不自动应用建议。
- [设置 · AI 与场景](10-settings-ai.png)：连接、场景、用量三段；密钥仅钥匙串。
- [设置 · 外观与代码](11-settings-appearance.png)：应用主题、日夜模式、代码配色三组独立设置，附代码预览。
- [SVN → Git 迁移](13-migration.png)：步骤、转换预览、作者映射、目标状态；发布前仍可打开结果核对。

### 辅助弹窗

- [辅助弹窗板](15-utility-dialogs.png)：更新工作区、初始化版本控制、按块/按行提交、添加忽略规则。
- 初始化只能单选一种版本控制方式；按块提交仅 Git；忽略规则只写本地。

## 覆盖说明

本版重点覆盖所有**一级页面**和**高风险确认弹窗**。下面这些低频工具页复用同一套弹窗骨架，但没有在本轮逐张放大：

| 页面 | 复用方式 |
| --- | --- |
| 已关联工作副本 | 头部 + 列表 + 单个「移除关联」，与「最近打开」同构 |
| 搁置未完成改动 | 头部 + 创建搁置 + 列表，与「忽略规则」同构 |
| 迁移作者通讯录 | 设置窗口内的表格页，与「设置 · AI」同构 |
| 继续已有迁移 | 选择列表 + 确认，与「最近打开」同构 |
| 文档 / 表格 / PDF 预览 | 工作区右栏的只读内容面，保留 macOS 快速查看提示 |
| 追溯 / blame、比较版本 | 历史页的代码面 + 窄信息列，不另起视觉语言 |
| 提交 / 更新的进行中与结果 | 共享传输进度和结果面板，颜色与语义沿用本套系统 |

如果这些页面也要定稿，我可以按同一套组件继续补 5–7 张，不需要重新定风格。

## 交互与原生落地

- **顶栏**：仓库和分支在左，视图切换居中，拉取/推送/AI 审查在右。设置不重复出现在 AI 审查旁边。
- **弹窗**：70 点标题区、66 点底部操作区；关闭在右上，主操作只在底部一次。危险动作不放在关闭按钮附近。
- **分栏**：主页面继续支持拖动；窄窗优先收紧左栏和提交栏，不压缩代码阅读到不可读。
- **主题**：应用主题、日夜模式、代码配色继续独立；本套 C 方案只定义浅色界面，深色需要按同一 token 反向生成。
- **可访问性**：所有交互控件保留原生语义；差异状态不只用颜色；代码字号、行高和控件高度在 SwiftUI 中应使用点值而不是截图比例。
- **真实数据**：图中的仓库、提交、分支、作者、文件数、同步状态与 AI 结果都是示意。实现时以 `WorkspaceModel`、历史分页、`RepositoryCommitModel` 等现有状态为准，不为贴图伪造数据。

## 复现

```sh
node docs/design/canvas-2026-10-22/src/render.mjs
node docs/design/canvas-2026-10-22/src/pdf.mjs
```

源文件位于 `src/`：`styles.css`、`sprite.js`、各页面 HTML、`render.mjs`、`pdf.mjs`。所有页面共用 `styles.css` 中的 token 与组件；页面差异只在内容与组合，不在另起一套视觉。

> 下一步建议：先在工作区和提交核对上落这套组件，确认分栏、代码密度和弹窗层级后，再向历史、设置和迁移铺开。
