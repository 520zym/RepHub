仅使用独立 QA 应用和临时 Git 仓库。截图由原生窗口直接捕获并保存，保存后重新读取检查；没有操作正式仓库。

1. [工作区](01-current-workspace.png)：文件树、代码高亮和并排差异已可用；底部历史与工作区同时显示，挤占代码高度。提交表单呈细横条，选文件与提交范围关系不明显。主工具栏的图标需要进一步区分导航、操作和辅助工具。
2. [历史页](02-current-history.png)：提交、文件和差异能联动；分支、提交列表、元数据检查器与底部差异同时展开，形成多个同等权重区域。文字和状态有较小字号，实际对比度、键盘焦点与辅助功能仍需在实现中验证，本轮不宣称无障碍合规。

## 拟调整的信息层级

- 顶部固定仓库/分支、工作区/提交历史导航、拉取或更新、Git 推送。打开本地目录与远端克隆/检出继续从仓库入口进入；不在侧栏堆放全局仓库列表。
- 工作区以“勾选文件 → 阅读差异 → 写说明 → 提交”为主线。文件树提供“变更/全部文件”；AI 生成只在提交说明旁，其他高级能力收于上下文或更多菜单。
- 历史默认独立占满窗口。分支导航可收起；选提交后提供文件树与差异，元数据按需展开。底部历史作为用户主动打开的辅助视图，不默认挤占日常工作区。
- 文件级“文件历史”靠近路径与差异标题。逐行追溯、忽略、搁置等继续可发现，但不与提交抢主按钮。
- 冲突出现时，在工作区上方提供一个明确处理入口，文件列表将冲突置前。冲突解决界面继续使用基准/本地/传入和可编辑结果。被冲突阻塞的提交必须给出原因。
- Git 拉取与推送分别呈现；SVN 显示更新与直接提交，不显示 Git 式推送。共管目录在执行前明确目标，各绑定独立显示结果。示例中两个目标复选框用于已有共管目录，并不改变初始化只能单选的要求。

## 三张候选稿

编号严格按本轮聊天中的生成图显示顺序：

1. [左侧提交区](option-1-left-commit.png)：文件选择与提交表单在一列，差异获得最大连续高度。主要取舍是左侧文件树与表单共享高度，需要可折叠表单和独立文件滚动。
2. [右侧提交检查器](option-2-commit-inspector.png)：文件、差异、提交形成三段任务顺序，适合检查提交目标；检查器可折叠，较窄窗口以统一差异为主，避免并排代码过窄。
3. [底部提交区](option-3-bottom-commit.png)：保留现有使用习惯，表单有足够高度和明确分组。画面展示冲突阻塞状态，突出解决冲突而非提交。主要取舍是占用部分代码高度。

生成图用于比较结构和观感，局部图标、代码行号和计数不作为实现规格。正式实现应直接使用真实数据、现有语义图标和版本控制抽象；先按选定方向细化，再改 SwiftUI。

## 视觉约束与提示词要点

三张均以当前原生工作区截图及 `../workspace-reference.png` 作为实际附图。生成提示词要求单张 1440×960 的正面 macOS 窗口、中文系统字体与等宽源码、主体为文件差异，不生成营销页面或仪表盘。

- 原生导航轻材质；代码与正文为稳定实色。区域以背景色、间距和对齐区分，禁止可见分割线、面板描边、表格网格和重复阴影。
- 基底 `#F6F8F4`、内容 `#FDFEFD`、侧栏 `#EDF3EE`、文字 `#213B33`、次级 `#64786E`、强调 `#087E5E`、选中 `#D9EEE4`。增删保留浅绿/浅红及符号；冲突使用克制暖橙及明确文字。
- 正文约 13–15pt，代码约 13pt；常用控件圆角约 8pt，主要区域间留白 12–20pt。应用主题、代码配色、日夜模式继续独立，设计稿仅呈浅色示例。
- 每图一个当前主动作；日常是提交，有冲突时是解决冲突。没有底部常驻历史、AI 主面板、迁移卡片、指标卡或功能展示墙。
- 第一张提示强调左文件树下方提交说明、目标选择与主按钮，右侧并排差异全高；第二张强调左文件、中统一差异、右可收起提交检查器；第三张强调上方冲突提示、左右文件与差异、底部提交表单被冲突禁用。

## 参考来源

- [Apple Materials](https://developer.apple.com/design/human-interface-guidelines/materials)：材质用于层次，Liquid Glass 集中在导航和控制层，内容区保持清楚。
- [Apple Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars)：按功能与使用频率分组，减少拥挤，主动作位置稳定。
- [Apple Designing for macOS](https://developer.apple.com/design/human-interface-guidelines/designing-for-macos/)：利用桌面空间减少嵌套和模态，保留可调整窗口与键盘路径。
- [Tower Interface Overview](https://www.git-tower.com/help/guides/first-steps/tower-overview/mac)：文件选择、差异查看与提交区域的任务组织。
- [Fork](https://git-fork.com/)：差异、历史及冲突处理围绕日常版本管理。参考其功能分工，不复刻其外观。

上述来源用于设计研究；两张本地截图才是当前 RepHub 布局评估证据。
