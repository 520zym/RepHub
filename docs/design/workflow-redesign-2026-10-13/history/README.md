## 显示顺序与用途

本轮聊天中三张生成图的实际显示顺序：

1. [图谱与差异上下联动](option-1-graph-and-diff.png)：左侧分支树，上方提交列表，下方变更文件树与并排差异。适合同时辨认分支关系和比较代码；代价是差异的可见高度较少。
2. [连续历史与沉浸差异](option-2-history-reader.png)：左侧提交列表，右侧提交摘要、可收起的文件树和统一差异。适合连续点选提交、阅读代码；分支树从列表顶部展开，提交标题需允许省略并查看完整内容。
3. [SVN 单文件历史](option-3-svn-file-history.png)：展示进入文件历史后的独立范围；左侧修订记录，右侧选定修订的差异。它是状态补充，可与前两张任一主历史布局组合，而非要求所有历史只看一个文件。

## 实现时必须保持

- Git 的分支树、提交图与推送语义不套给 SVN。SVN 显示修订号及工作副本 BASE；混合修订时明确“需核对”。
- Git 同步判断保留当前分支及已获取上游范围和时间；未配置上游/游离 HEAD 显示未知。逐条待更新/待推送/需核对状态仍须可见。
- 历史和文件历史继续分页，滚动近底加载；保留手动加载、取消、重试和已到最早状态。搜索须区分已加载过滤和全历史搜索。
- 单文件历史显示完整路径和范围，可返回全部历史；Git 跟随改名、SVN 保留 peg revision，删除文件历史仍可查。
- 变更文件保持树结构和独立展开状态，状态徽标不可被缩进挤掉。完整提交说明、版本比较、AI 审查从上下文展开，不堆成常驻按钮。
- 面板可拖动调整并保留布局状态。统一/并排差异可切换；窄窗口默认统一或允许用户收起辅助区，不能将代码挤成窄条。
- 去除可见面板线、表格线和列表分隔线，以背景色及留白区分；Git 图谱连线属于数据，仍保留。生成图中个别浅线和示例图谱拓扑不是最终规格。
- 生成图的代码、路径层级、分支引用、计数和同步徽标仅说明布局；不代表真实拓扑或实现契约。正式 UI 从抽象层真实数据绘制，绝不照抄示例代码的具体适配器依赖。
