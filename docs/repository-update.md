# 已有仓库更新

本轮提供已有工作副本的更新，不包括克隆、检出、初始化、提交或推送。顶部刷新图标仅重新读取数据，“更新”打开实际操作窗口。

## 操作语义

| 操作 | 行为 | 停止条件 |
| --- | --- | --- |
| Git 获取远端 | 从当前分支明确配置的上游远端 fetch，更新远端跟踪引用，不改工作文件 | 无上游、游离 HEAD、远端无效或 fetch refspec 指向本地分支等非远端跟踪范围 |
| Git 更新 | fetch 后比较提交，仅允许快进到已核验的上游 SHA；本地领先时保留本地提交 | 已跟踪修改、分叉、合并/变基进行中、未跟踪或忽略路径冲突、操作期间目标变化 |
| SVN 更新 | 只读探测连接后执行一次 update，保留本地修改及冲突，显示路径结果 | 已有冲突、认证/证书失败、其他命令错误；失败后核对实际状态 |

Git 本轮不自动 stash、reset、clean 或 rebase，不运行仓库 hooks；包含子模块的目标版本及配置 Git 文件过滤器（含 LFS）的环境会明确停止，不进行不完整检出。SVN 不更新 externals，不自动解决冲突、revert 或 cleanup。

双管控目录每次只选一个来源进行更新。两侧状态会一起刷新，因此 SVN 更新后的文件可能成为 Git 本地变更，反之亦然。两边状态不同是实际版本基准的差别，客户端不会自动提交或强制同步另一侧。

## 进度、取消和故障

显示实际阶段，不显示估算百分比。操作和完成后的状态核对期间，打开目录、切换来源、重复更新等入口锁定。正常退出会提示等待或取消操作。

取消会终止进行中的子进程，但不会回滚已完成的文件写入或远端引用更新。成功、冲突、失败、取消后都会重新检测工作区并读取全部绑定；部分读取失败单独展示。网络失败可能留下部分结果，不能把失败等同于“完全未修改”。

旧 SVN 使用只读 `info` 确定现代或兼容 TLS 模式，然后按该模式执行一次 `update`。写命令不直接套用自动降级重试，也不绕过证书验证。TLS 策略详见 [连接兼容](svn-tls-compatibility.md)。

## 隔离验证

更新自动化测试通过 `LocalRepositoryFixture` 建立独立 HOME、Git bare 远端、SVN `file://` 服务库、读写工作副本和双管控目录。隔离运行器不继承个人 Git 全局配置、SSH Agent 或代理变量。没有测试指向业务仓库或业务远端。

原生界面样本通过以下命令生成，不覆盖或删除已有目录：

```sh
python3 scripts/create-update-fixtures.py
```

输出位于 `系统临时目录/RepHub-UpdateFixtures/<uuid>`，包含 `git-update`、`git-dirty`、`git-diverged`、`svn-update`、`svn-conflict`、`dual`。所有远端均在同一夹具根目录；不要用正式仓库替代这些样本。原生应用仍使用日常启动配置，窗口验收只打开这些本地样本。

本轮验证范围和结果记录在 [原生验证记录](native-verification.md)。本地 file 协议更新通过不代表旧 HTTPS 服务端写入已获验收；本轮不使用业务服务做写入测试。
