# SVN 迁移并发预取验收

日期：2026-10-15。本轮所有迁移和写入验证均使用临时 Git / SVN 夹具，没有对 EFB 正式仓库执行迁移、更新、提交或推送，也没有用真实旧 TLS 服务做性能测试。

## 实现范围

- 新目录初迁、当前工作副本初迁自动预取下一份来源快照，与当前版本的扫描、Git 写入及核对重叠。队列最多保留一份未消费快照，不并行切换同一个 SVN 工作副本，也不并行创建 Git 提交。
- SVN 固定 peg 的历史节点 `info` 与隔离缓存的 `checkout/switch` 并行；两者成功后继续核对 URL、UUID、精确修订、工作副本状态，再导出本地快照。
- Git 提交后一次查询读取提交号和父级，每个修订减少一次进程启动；父级检查和对象内容核对保留。
- 取消消费会传播到预取任务，服务在失败或取消后等待后台任务退出才清理缓存。只给已核对修订保存映射及检查点；恢复重新建立来源缓存。
- 后台进度附在当前阶段详情中，不提前推进修订完成数、不混用速度、不重复追加前台文件记录。等待预取时有单独的前台状态。
- 补迁与不支持已验证 Git 会话的目标仍走原有串行路径。

## 本地对照

同一 `file://` SVN 子目录，4 条修订、320 个静态小文件，包含修改、删除和新增。两个运行均使用相同的已验证 Git 会话，仅通过内部测试参数切换预取；应用界面不增加开关。

| 配置 | 初迁总耗时 | 提交数量 | 最终文件树 |
| --- | ---: | ---: | --- |
| 串行来源准备 | 11.638 秒 | 4 | 与 SVN 最终导出一致 |
| 单份预取 | 8.215 秒 | 4 | 与 SVN 最终导出一致 |

该次样本耗时减少 **29.4%**。计时包含隔离 Git 初始化、SVN 快照准备、来源扫描、Git 写入与核对、检查点以及最终导出核对；不含测试仓库创建、日志预检及计时后的独立审计。基准为 Debug 配置，按串行、预取的顺序各运行一次，文件系统缓存及磁盘争用均可能影响结果，不能作为真实远程 SVN 的提速保证。首次快照尚无前一版 Git 工作可重叠，后续修订才获得流水并行收益。

原始耗时与进度事件见 [local-benchmark.json](local-benchmark.json)。事件是异步进度回调，不是精确 CPU、磁盘或网络阶段计时；测试不设置必须提速的阈值。

## 验证

30 项不同的针对性测试最终通过，没有运行全量测试：

| 范围 | 数量 | 覆盖 |
| --- | ---: | --- |
| 预取与业务服务 | 6 | 两种初迁接线、真实任务重叠、单页上限、顺序、消费取消、失败停止、进度隔离 |
| 原有编排与恢复 | 13 | 当前工作副本边界、固定来源、旧检查点恢复、未核对提交拒绝 |
| SVN 会话 | 5 | `info` 与隔离检出重叠、查询失败阻止导出、精确修订、本地基线和缓存顺序 |
| Git 对象会话 | 2 | 精确父级串联、类型/执行位变化、对象内容、外部 HEAD 改动拒绝 |
| 真实本地集成 | 3 | 两种初迁逐版本内容对照、预取期间失败后恢复不重复提交、缓存篡改拒绝 |
| 本地性能对照 | 1 | 相同工作量串行/预取对照与最终树独立审计 |

测试开发中修复了夹具的重复作者字典、快照所有权断言及错误拦截本地 SVN 核对等问题，未放宽生产校验。最终结果分别记录在本机 `/tmp/rephub-prefetch-core.log`、`/tmp/rephub-prefetch-integration.log`、`/tmp/rephub-prefetch-benchmark.log`；较早的 `/tmp/rephub-prefetch-targeted.log` 包含修复前失败及已经通过的 Git、原有 SVN 用例，不能单独当作最终通过报告。

`scripts/build-app.sh release` 和 `codesign --verify --deep --strict build/RepHub.app` 通过，已启动更新后的原生应用，确认 RepHub 窗口与迁移入口正常可用。打包采用 Release 优化配置；该构建本身不计入上面的性能对照。未在原生窗口中启动正式迁移。
