# 代码追溯、审查与本地整理

所有新增版本控制能力由 VersionControlCore 的独立协议定义，经 RepositoryService 调度，Git／SVN 适配器负责具体工具语义。写操作共享原有仓库锁，不创建额外工具通道。

| 功能 | 入口 | 行为与边界 |
| --- | --- | --- |
| 逐行追溯 | 工作区文件右键 → 逐行追溯 | Git/SVN 已提交文本，固定修订；显示行号、作者、日期、版本，点击进入提交详情。未跟踪文件不伪造来源。 |
| 全历史搜索 | 历史页或项目菜单 | 提交说明、作者、日期、精确文件路径；按固定游标每次最多扫描 300 条，显示已扫描数量，可继续到最早提交，也可取消。主列表原有搜索仍只过滤已加载记录。 |
| 内容冲突编辑 | 冲突文件右键或仓库管理 | 基准／本地／传入三栏、可编辑结果，逐块选择一方或两边；校验原内容后保存并标记解决，不自动提交。拒绝未处理标记、二进制、链接、树／属性冲突和缺少三份内容的冲突。 |
| 搁置与恢复 | 项目／仓库菜单 | 命名、范围预览、包含未跟踪文件、仅保存或保存并清理；恢复后保留记录，删除需确认。 |
| Git 部分提交 | 已修改文件右键 | 选择块或单行，先预览最终补丁再提交。选中文件已有暂存改动时要求先取消该文件暂存；其他文件的暂存保留。首个提交、二进制、新增／删除／重命名使用普通文件提交。不会推送远端。 |
| 忽略规则 | 未跟踪项目右键 | Git 写 .gitignore，SVN 写父目录 svn:ignore；先预览，保留既有规则，过期预览拒绝执行。不会自动提交。 |
| AI 问题定位 | AI 审查结果 | 结构化问题含严重程度、路径、新版本行号、原因、建议；位置必须存在于实际发送的补丁中。可标记已处理或忽略，定位前重查代码快照。自定义纯文本响应仍完整保留。 |
| 差异阅读 | 差异标题栏 | 忽略空白仅影响显示，原始补丁及 AI/提交输入保持不变；行内改动使用更深背景，保留语法颜色，超长行降级为整行提示。 |
| 迁移源提醒 | 底部提示／仓库菜单 | 有本地 SVN→Git 迁移记录时，前台空闲期间约每 5 分钟只读检查源 SVN；可暂停、手动检查。点击新修订提醒进入已有补迁预览，绝不自动迁移或推送。 |

## 搁置的能力差异

Git 使用 stash；仅保存会在保存后恢复原工作区和暂存状态，恢复失败时保留 stash 并明确报告。恢复可能发生冲突，记录不会自动丢弃。

SVN 使用本机 `Application Support/RepHub/Shelves` 下的文本快照，支持 UTF-8 受管修改与未跟踪普通文件（单文件最大 8 MiB）。拒绝属性修改、复制、冲突、特殊文件及未跟踪目录整树；不使用实验性 SVN shelve。恢复时核对 BASE、原内容和快照哈希；不覆盖新改动。测试显式使用临时快照目录。

## 迁移源提醒

只比较该 SVN 目录的最新修订与本地迁移记录的末端，不以仓库全局修订号差值冒充提交数量。源 URL、仓库 UUID 和迁移记录前后一致性均需通过核对；错误保留已有提醒并显示失败，不宣称已同步。无记录的目录不访问远端。当前通知是应用内提示，不申请系统通知权限。
